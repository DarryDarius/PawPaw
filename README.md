# PawPaw MVP Demo

这是根据 `mvp.md` 和 `code.md` 实现的第一版可运行 Demo。

当前版本优先验证主链路：

1. 创建宠物档案
2. 发布宠物动态
3. 点赞、收藏、举报
4. 记录健康事项
5. 浏览附近和本地服务
6. 提交服务线索
7. 在运营后台处理审核和线索

## 核心功能与优先级

PawPaw 的核心功能是：以宠物档案为中心，把养宠记录、宠物社交、本地服务和运营审核串成一个轻量宠物社区。

### P0 必须优先做

1. 宠物档案：创建宠物档案，包括名字、物种、品种、生日、性别、头像、城市和可见性。ok
2. 用户与宠物绑定：主人账号和宠物档案绑定，支持一个用户拥有一个或多个宠物。ok
3. 宠物动态发布：用户可以选择宠物发布图文动态。ok
4. 动态流浏览：支持推荐、最新、关注、城市等基础 Feed。ok
5. 基础互动：点赞、收藏、评论、举报。ok
6. 健康记录：记录体重、疫苗、驱虫、绝育、喂养等基础事项。
7. 健康提醒：疫苗、驱虫等提醒，用来增强持续回访。
8. 本地服务目录：展示洗护、寄养、医院等本地服务商。
9. 服务线索提交：用户向服务商提交咨询或预约意向。
10. 内容审核与举报处理：新动态、举报内容进入运营后台处理。

### P1 主链路稳定后做

1. 附近宠友：按城市或片区展示附近宠物和宠友，默认不暴露精确位置。
2. 宠物友好地点：公园、咖啡店、步道等地点信息。
3. 新手问答：围绕喂养、驱虫、疫苗、行为训练等问题做轻问答。
4. 消息中心：点赞、收藏、评论、系统提醒、服务线索状态通知。
5. 商家后台：商家查看和处理用户咨询线索。
6. 运营后台：审核队列、举报处理、服务商管理、基础数据看板。
7. 隐私与可见性设置：控制宠物档案、动态、位置、健康记录的可见范围。

### P2 后续增强

1. 关注关系：关注用户或宠物，形成更稳定的社交关系。
2. 评论楼层和回复：支持更完整的讨论能力。
3. 多人共养：家庭成员共同管理同一只宠物档案、健康记录和提醒。
4. 服务商评价：用户对洗护、医院、寄养等服务打分和评价。
5. 更完整的推荐系统：按宠物类型、城市、兴趣、互动行为推荐内容。
6. 宠物主页：沉淀宠物成长记录、健康记录、动态合集。
7. 数据埋点与漏斗分析：分析注册、建档、发帖、健康记录、线索提交等关键转化。
8. 移动端 App：在 Web 主链路验证后扩展移动端。

### P3 暂时不优先

1. 自营商城
2. 担保支付
3. 复杂订单履约
4. 直播
5. 长视频
6. 达人商业化
7. 全国范围附近匹配
8. 复杂 AI 推荐

### 推荐开发顺序

1. 宠物档案和用户绑定
2. 动态发布和动态流
3. 点赞、收藏、评论、举报
4. 健康记录和提醒
5. 本地服务目录和线索提交
6. 运营后台审核
7. 商家后台处理线索
8. 附近宠友和地点
9. 问答和消息中心
10. 数据统计、隐私完善、移动端扩展

## 当前宠物档案实现范围

当前 Web Demo 已把宠物档案作为独立模块实现：

1. 顶部导航新增“档案”入口。
2. 支持创建宠物档案：名字、物种、品种、生日、性别、头像 URL、城市、可见性。
3. 支持编辑宠物档案，并校验名字长度和生日不能晚于当前 Demo 日期。
4. 支持多宠物管理、切换当前使用宠物、设置默认宠物。
5. 档案页展示当前宠物的动态数、健康记录数、服务线索数和下次提醒。
6. 发布动态、记录健康、提交服务线索都会关联当前宠物。
7. 附近页会尊重宠物可见性，“仅自己”不会出现在附近宠友列表。
8. 数据库迁移已补充宠物档案字段、枚举约束、主人关系和单用户默认宠物约束。

## 当前用户与宠物绑定实现范围

当前版本已把“主人账号和宠物档案绑定”拆成独立关系模型：

1. Web Demo 状态中新增 `ownerPetBindings`，不再把默认宠物和角色直接写在宠物实体上。
2. 创建宠物时会自动给当前用户创建 `owner` 绑定；第一只 active 绑定宠物会自动成为默认宠物。
3. 支持多宠物绑定、切换当前使用宠物、设置单用户默认宠物。
4. 发布动态、记录健康、提交服务线索前都会校验当前用户是否对该宠物有 `owner` 或 `family` 绑定。
5. 编辑宠物档案、设置默认宠物要求 `owner` 绑定。
6. 宠物列表只展示当前用户 active 绑定的宠物，前端选择器也只使用已绑定宠物。
7. Go API 骨架新增 `/api/me/pets`、`POST /api/pets`、`PATCH /api/pets/:id`、`POST /api/pets/:id/set-primary`、`DELETE /api/pets/:id/binding`，目前使用内存数据演示绑定规则。
8. 数据库迁移中的 `owner_pets` 已包含角色、状态、邀请人、默认宠物唯一约束和更新时间字段。

## 当前宠物动态发布实现范围

当前版本已把“宠物动态发布”升级为围绕宠物绑定和审核流转的内容模块：

1. 发布动态时只能选择当前用户 active 绑定且角色为 `owner` 或 `family` 的宠物。
2. 动态数据支持 `petIds`、话题、正文、图片 URL、可见性、审核状态和创建时间。
3. 发布表单支持话题选择、可见性选择、正文 1000 字限制、最多 9 张图片 URL。
4. 新发布动态默认状态为“待审核”，并自动进入运营后台审核队列。
5. 首页 Feed 会按可见性过滤，“仅自己”动态只对绑定该宠物的用户可见。
6. 宠物档案页展示该宠物最近动态和关联动态数量。
7. 举报动态会创建带 `postId` 的审核任务；后台处理时只通过对应动态。
8. Go API 骨架新增 `POST /api/posts`、`GET /api/feed`、`GET /api/pets/:id/posts`，目前使用内存数据演示发布权限和 Feed 读取。
9. 数据库迁移已补充 `posts.topic`、`posts.visibility`、互动计数字段、帖子约束和 `post_media` 图片表。

## 当前动态流与基础互动实现范围

当前 Web Demo 已实现基础 Feed 和互动闭环：

1. 首页 Feed 支持“推荐、最新、关注、城市”四种模式。
2. 推荐流会按同城、当前绑定宠物、审核状态、图片数、点赞、评论和收藏综合排序。
3. 最新流按创建时间倒序展示。
4. 关注流展示当前用户已绑定宠物相关动态。
5. 城市流展示同城且非“仅自己”的动态。
6. Feed 会尊重可见性和审核状态：未通过内容不展示，待审核内容仅对关联宠物的绑定用户可见。
7. 支持点赞/取消点赞，并实时更新点赞数。
8. 支持收藏/取消收藏，并实时更新收藏数。
9. 支持提交评论，单条评论最多 200 字，动态卡片展示最新评论。
10. 支持举报动态，同一条动态待审核举报不会重复提交，举报会进入运营后台。

## 本地运行

```bash
npm install
npm run dev
```

打开终端输出的本地地址即可访问 Web Demo。

## 构建

```bash
npm run build
```

构建产物会输出到 `dist/`，可部署到 GitHub Pages、Vercel、Netlify 或任意静态托管服务。

## 后端骨架

`apps/api/cmd/api/main.go` 目前提供最小健康检查：

```bash
go run ./apps/api/cmd/api
curl http://localhost:8080/healthz
```

后续可以按 `code.md` 中的模块逐步替换 Web Demo 的本地状态。
